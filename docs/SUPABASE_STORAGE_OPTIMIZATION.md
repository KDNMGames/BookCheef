# Supabase: автоматическое создание профиля и экономия места

## Регистрация пользователей

Регистрация выполняется Supabase Auth. Миграция `202611060003_auto_user_profiles.sql` устанавливает триггер на `auth.users`: после успешного создания Auth-пользователя автоматически появляется одна минимальная запись в `public.user_profiles`.

В таблице хранится только `user_id`, ссылающийся на `auth.users.id`. Email, пароль, дата регистрации и токены не копируются. Миграция также создаёт минимальные записи для уже существующих аккаунтов.

Это единый механизм для сайта и Android. Не добавляйте ручной INSERT профиля в клиентские приложения: это создаст дублирующую логику и потенциальные ошибки.

## Что оптимизировано и что проверять

- Каталог книг отдаётся через `book_catalog`, который не раскрывает содержимое книг.
- Полный контент книги должен запрашиваться через `get_book_content`, сохраняющий правила доступа к платным книгам.
- Крупные файлы (PDF, DOCX, обложки, иллюстрации) хранить в Supabase Storage; в PostgreSQL держать только ссылки и компактные метаданные.
- Не копировать email и другие Auth-поля в отдельные таблицы.
- Не добавлять индексы «на всякий случай»: они занимают дисковое место.
- Не удалять существующие столбцы/индексы автоматически. Для точной оптимизации нужны фактические размеры таблиц, индексов и статистика запросов из проекта.

## Применение

Открой Supabase → SQL Editor и выполни файл миграции целиком. Это добавляющая миграция: она не удаляет таблицы, книги, аккаунты или Storage-файлы.
