# BookCheef: алгоритм генерации одной законченной книги

Статус: проектирование новой одноразовой генерации. Это не потоковый генератор и не восстановление прежней очереди.

## 1. Контракт одной генерации

Один запрос администратора в Telegram создаёт ровно одну книгу. Повторное нажатие/повтор webhook с тем же request_id не должно запускать вторую генерацию (идемпотентность).

Команда интерфейса: `/book <тема или подробное ТЗ>`. Если тема не задана, бот запрашивает её и не расходует лимиты до получения ответа.

До первого обращения к генеративной модели бот отправляет отчёт по каждому настроенному провайдеру:
- провайдер и модель;
- доступен ли ключ/секрет;
- известен ли бесплатный тариф;
- доступная квота/остаток и время сброса, если провайдер действительно предоставляет эти сведения;
- результат безопасной проверки доступности;
- статус: доступен / исчерпан / cooldown / неизвестно / отключён.

Нельзя выдавать предполагаемый остаток за измеренный. Если API провайдера не раскрывает квоту, показывать «неизвестно» и отдельно — результат минимального бесплатного health-check. Не выполнять платные тестовые запросы.

После предварительного отчёта генерация запускается только если есть хотя бы один подтверждённый бесплатный маршрут. Если все бесплатные маршруты недоступны, бот сообщает об этом и сохраняет только запрос и причину отказа; никаких платных fallback.

После генерации бот отправляет второй отчёт: фактически использованные модели, число запросов/токенов если известно, ошибки и cooldown, статус иллюстраций, слова/главы, проверки структуры и итог публикации.

## 2. Целевой объём и структура

Длительность чтения оценивается, а не гарантируется: целевой объём — 18 000–22 000 русских слов, с настройкой по возрасту и жанру. Для детской книги допустима меньшая скорость чтения и соответствующая корректировка объёма; целевой объём рассчитывается из заявленной аудитории.

Рекомендуемая структура:
1. Тема, аудитория, жанр, обещание книги и краткая аннотация.
2. План из 12–16 глав с причинно-следственной аркой.
3. Полный текст глав по одной за запрос/порцию, с сохранением контрольной точки после каждой главы.
4. Сквозная проверка имён, хронологии, фактов, мотивации, незакрытых линий и повторов.
5. Финальная редактура: связность переходов, стиль, орфография, возрастная уместность.
6. Иллюстрации: обложка + ориентировочно 1 иллюстрация на главу (или чаще по ТЗ). У каждой иллюстрации — описание сцены, alt-текст, привязка к главе/позиции и источник/лицензия.
7. Сборка в полный BookCheef JSON без заглушек, сокращений вида «далее», пустых глав и вымышленных ссылок.
8. Валидация по фактической длине, структуре, ссылкам на изображения и совместимости с текущим импортёром.
9. Только после успешной валидации — публикация. При ошибке книга остаётся непубличным черновиком и бот сообщает точную причину.

## 3. Оркестрация провайдеров

Провайдеры должны быть описаны конфигурацией, а не жёстко зашиты в бизнес-логику. Для каждого адаптера обязательны:
- `checkAvailability()`: ключ, бесплатный статус, доступная квота только если есть официальный endpoint;
- `generate()`: один ограниченный запрос с timeout, retry только на временные ошибки;
- `classifyError()`: quota, rate_limit, cooldown, auth, billing_required, network, invalid_response;
- `usage()`: фактические счётчики только из ответа провайдера.

Приоритет маршрутов задаётся настройкой. Платные модели/платные endpoints должны быть запрещены allowlist-политикой, а не только флагом в промпте. Нельзя автоматически включать биллинг, пополнять кредиты или делать запросы, если бесплатный режим не подтверждён. Любой ответ с признаком оплаты/billing_required блокирует провайдера.

Остаток квоты часто не доступен через API. Для таких провайдеров честный отчёт показывает «неизвестно»; не надо пытаться вычислять остаток из числа запросов.

## 4. Участие ChatGPT в генерации

Текущий экземпляр ChatGPT в этой беседе не является API endpoint, который Edge Function или Telegram-бот может вызвать автоматически. Подписка ChatGPT также не предоставляет приложению бесплатный API-доступ.

Поэтому корректный fallback без платных API — режим ручной передачи:
1. Если все автоматические бесплатные провайдеры исчерпаны, бот ставит одну книгу в статус `awaiting_assistant`, сохраняет текущую главу/план и отправляет отчёт.
2. Пользователь передаёт сюда тему и сохранённую контрольную точку (или запускает поддерживаемую передачу данных).
3. ChatGPT продолжает текст, редактуру, структуру JSON и иллюстрационные промпты в рамках текущего диалога.
4. Результат возвращается в BookCheef через импорт JSON/защищённую команду подтверждения.
5. До проверки книга не публикуется.

Нельзя обещать, что ChatGPT автоматически подхватит генерацию из Telegram без отдельного официального интеграционного канала. Нельзя использовать скрытый платный API или ключ пользователя ChatGPT.

## 5. Состояния одной книги

Допустимые состояния: `requested` → `preflight_reported` → `generating` → `editing` → `illustrating` → `validating` → `ready_to_publish` → `published`.

Дополнительные терминальные/ожидающие состояния: `awaiting_free_quota`, `awaiting_assistant`, `failed`, `cancelled`.

У записи одной книги должны быть: request_id, тема/ТЗ, выбранная аудитория, статус, план, номер последней завершённой главы, накопленный текст, ссылки на иллюстрации, журнал вызовов провайдеров, отчёты preflight/postflight, ошибки и временные метки. Черновик и checkpoint обновляются после каждой главы, чтобы не потерять прогресс при timeout.

Для первой версии допускается только одна активная книга одновременно. Никакой периодической генерации, автоматического пополнения очереди или запуска следующей книги.

## 6. Защита от неполной книги

Публикация запрещена, если:
- объём существенно ниже целевого диапазона без явного согласования;
- отсутствует обложка или требуемые иллюстрации;
- главы пусты, дублируются или содержат заглушки;
- не заполнены обязательные поля BookCheef JSON;
- иллюстрации не имеют проверяемых URL и лицензии/происхождения;
- проверка импорта не пройдена;
- итоговый postflight-отчёт не сформирован.

«Успешная генерация» означает только `published` после подтверждённой публикации. Создание файла или черновика успехом публикации не считается.

## 7. Этапы реализации

1. Реализовать в Telegram-боте запрос одной книги, preflight/postflight-отчёты и защиту от повторных запусков.
2. Добавить таблицу состояния одной книги и защищённое хранение контрольных точек.
3. Подключить только проверенные бесплатные адаптеры и лимитированные запросы.
4. Подключить генерацию/хранение иллюстраций с коммерчески допустимым происхождением.
5. Реализовать валидатор фактического BookCheef JSON и тестовый импорт без публикации.
6. Включить публикацию только после всех проверок.

## 8. Непереговорные ограничения

- Никаких платных API, платных моделей, платных изображений, покупки кредитов или включения биллинга.
- Никаких автоматических повторов, способных создать неожиданные расходы.
- Неизвестная квота обозначается как неизвестная.
- При исчерпании всех бесплатных лимитов — сохранить прогресс и перейти в `awaiting_assistant`, а не молча завершать короткую книгу.
- Существующие опубликованные книги, сайт и их изображения не изменять в рамках генерации.


## Implementation update — 2026-11-11

- Telegram bot has a checkpointed one-book worker and resumes after verified free quota returns.
- Completion assembles a non-published bookcheef-book-v1 draft with the current books table field shape.
- Deterministic checks report missing title/synopsis/genre/audience, chapter count/order, missing chapter titles, short chapters, duplicate chapters, placeholders, and total word count.
- Admin command /bookexport <request_id> sends the JSON draft as a Telegram document.
- Export is explicitly a draft: cover_url is empty, illustration prompts are metadata only, and can_import / can_publish remain false until assets and editorial review are completed.
- No live generation was run during implementation; no inference quota was consumed. The export command and validator are deployed but still require a real completed book for end-to-end verification.
